RR Trading One

First-run setup

Each step is checked against the running system. Do them in order; the sections below hold the buttons.

    First-time setup: create the administrator

    The engine has no users yet. Create the administrator account you will use to sign in to the Trading Console. The password is sent only to the local engine (127.0.0.1) and stored as an Argon2id hash.

    Backup and Recovery
    
        
    
          
    
      
    Backups are PostgreSQL dumps in this computer's backups folder (see Locations), encrypted
        with this installation's backup key: taken on request, before every database migration, before every restore, and
        automatically once a day while the database is running (the newest 14 are kept). Once a week the newest backup is
        restored into a scratch database and checked against the live one. Restoring replaces the whole database in one transaction, after a
        safety backup of the current one; afterwards auto trading is OFF and the engine reconciles with the broker before any
        entry. The trading worker is not restarted.

    Import from the previous Ubuntu server
    
      
    On the server, run scripts/migrate_export.sh: it writes rr_migrate_<stamp>.dump and its
        .manifest.json without changing anything on the server. Copy both to this computer (same folder) and add the dump
        (a dump from scripts/backup.sh also works, without the manifest check). It is first restored into a scratch database: if it does not
        restore cleanly, nothing is replaced. Then a safety backup is taken, the dump is restored and migrated to this version, every
        table's row count is compared with the verified dump, and the engine starts like a new installation (DEMO, auto trading OFF,
        LIVE approvals cleared). Afterwards: sign in with the server's user accounts, link the MT5 connector on this PC, re-enter AI
        provider keys and broker passwords (they were encrypted with the server's keys), and retrain models (the server's are unsigned here).
    
      
    
        
    
      
    
        
        
    
          
          
    
      
    
    
    

    
    
      
    Security
    
      
    Backup key
    
      
    Backups can only be read with this installation's backup key, which is protected by your Windows account.
        Write it down or store it offline: on a new PC (after a disk failure, for example) it is the only way to restore these
        backups. Anyone holding it and the backup files can read your database.
    
      
    
        
    
      
    
      
    Restoring another installation's backups: add that installation's key (it starts with RRBK1-).
    
      
    
        
    
      
    Rotate secrets
    
      
    Replaces the database and Redis passwords, the session signing key, the bridge secret and the local API key.
        A backup is taken first; the engine is stopped and started again; everyone is signed out. Keys that encrypt
        stored data (broker passwords, AI keys, models, backups) are not changed. The trading worker is not restarted.
